## 4. Ключевой момент: почему `div` компилируется и экспортируется под своим именем

### Проблема

В задании нужно экспортировать функцию `int div(int, int)`. Но:

- В `<stdlib.h>` (которое тянет `<windows.h>`) объявлена **встроенная функция компилятора**:
  ```c
  div_t div(int numer, int denom);   // возвращает частное И остаток
  ```
- При оптимизации `/O2` MSVC включает intrinsics. Увидев наше `int div(int,int)`, компилятор считает, что мы пытаемся переопределить свою встроенную функцию — типы не совпадают (`div_t` vs `int`):
  ```
  error C2169: div: подставляемая функция, определение невозможно
  ```

### Обычные «костыли» (НЕ работают или грязные)

| Подход | Результат |
|---|---|
| `#pragma function(div)` | Компилируется, но экспорт имени ломается |
| Обернуть в `namespace` | Всё равно C2169 (intrinsic видит имя) |
| `#define _CRT_DECLARE_NONSTDC_NAMES 0` | Не помогает, если `<windows.h>` уже подключён |
| Файл `.def` с `EXPORTS div=_div@8` | Работает, но **грязно** — имя в экспорте не `div`, нужно алиас, лишний файл |
| Переименовать функцию (`my_div`) | Нарушает ТЗ — имя задано преподавателем |

### Наше решение (два независимых фикса, **оба обязательны**)

#### Фикс 1: `/Oi-` через `AdditionalOptions` в `.vcxproj`

```xml
<AdditionalOptions>/Oi- %(AdditionalOptions)</AdditionalOptions>
```

> **Почему не `IntrinsicFunctions=false`?** В этой версии MSBuild этот параметр **не передаёт флаг в `cl.exe`** (проверено: в диаагностике `/v:diag` его нет, а `/O2` стоит). Только `AdditionalOptions` реально кладёт `/Oi-` в командную строку.

#### Фикс 2: Изоляция `<windows.h>` от кода функций

| Файл | Что включает | Почему |
|---|---|---|
| `pch.h` | **Только `<stdio.h>`** | Никакого `<windows.h>` → нет `<stdlib.h>` → нет объявления встроенного `div` |
| `SP.cpp` | `#include "pch.h"` | Видит только `<stdio.h>`, свою функцию `div` компилятор считает обычной внешней |
| `dllmain.cpp` | `#include <windows.h>` напрямую | Точка входа DLL нужна, но она **не использует PCH** (`<PrecompiledHeader>NotUsing</PrecompiledHeader>`) |

**Результат:** `dumpbin /exports SP.dll` показывает чистое имя:
```
    1    0 00001EAC div
    2    1 00001624 mul
    3    2 000019C0 sub
    4    3 00001534 sum
```
Никакого `.def` файла, никаких манглированных имен, никаких алиасов.

## 5. Почему это решение эффективнее «обычного»

| Критерий | Обычный подход (`.def` + полный PCH) | Наше решение |
|---|---|---|
| **Чистота экспорта** | Нужно прописывать алиасы в `.def`, имя в таблице экспорта может быть `_div@8` | Имя **ровно `div`** — как в задании |
| **Количество файлов** | `.def` + исправленный PCH + костыли в коде | **0 дополнительных файлов**, только разделение `dllmain.cpp` |
| **Переносимость** | `.def` — специфика MSVC, на Linux другой подход | Чистый C++: `extern "C"` + `/Oi-` работает везде |
| **Понятность для преподавателя** | «Я задал алиас в .def» — выглядит как магия | «Я отключил intrinsics и убрал windows.h из PCH» — инженерный подход |
| **Сборка на Linux** | `.def` не работает, нужен отдельный скрипт | Тот же `SP.cpp` собирается `g++ -fPIC -shared` без изменений |
| **Поддержка** | Забудь про `.def` — сломается экспорт | Изменения локальны: одна строка в `.vcxproj` + один файл `dllmain.cpp` |

## 8. Типовые вопросы преподавателя

**Q: Зачем вы вынесли DllMain в отдельный файл?**
A: Чтобы не включать `<windows.h>` в PCH. `<windows.h>` тянет `<stdlib.h>`, где объявлен intrinsic `div`. Если он виден в TU с нашей функцией — C2169.

**Q: Почему `/Oi-` в AdditionalOptions, а не IntrinsicFunctions=false?**
A: `IntrinsicFunctions=false` в этом MSBuild не доходит до `cl.exe` (проверено через `/v:diag`). Только `AdditionalOptions` гарантирует попадание флага в командную строку.

**Q: Можно ли было просто переименовать функцию?**
A: ТЗ требует имя `div`. Переименование — нарушение требований.

**Q: А если убрать `/O2`?**
A: Тогда теряем оптимизацию. `/Oi-` позволяет оставить `/O2` и при этом отключить только intrinsics.

**Q: Почему не `.def` файл?**
A: `.def` — легаси. Современный MSVC экспортирует `extern "C" __declspec(dllexport)` функции по имени без `.def`. Наше решение чище, переносимее и не требует сопровождения отдельного файла.

## 9. Итог

**Два маленьких изменения — чистое решение проблемы, которая ломает всем остальным:**

1. **Структурное:** `dllmain.cpp` с `NotUsing` PCH — изолирует Windows API от бизнес-логики
2. **Конфигурационное:** `/Oi-` в `AdditionalOptions` — отключает только intrinsics, оставляя `/O2`

Это **инженерный подход**: понимаем причину (intrinsic конфликт), устраняем её минимальными средствами, не добавляем технический долг (`.def`, переименования, прагмы).
